# MoWM v0.6 — Portable Execution ISA & Deployment Profiles

**Status:** Draft (design) · **Date:** 2026-06-21 · **Supersedes:** nothing (orthogonal extension of v0.1–v0.5)

---

## 1. Motivation

MoWM v0.1–v0.5 are a working neuro-symbolic mixture of world models: an axiom library +
HYLA world experts + learned routing + a deterministic logic engine + a VSA virtual machine
+ a self-organizing discovery loop, with ~2,900 tests. What it lacks is a way to run the
*same* programs across radically different substrates — a robot MCU, a neuromorphic chip, an
FPGA/ASIC, or the GPU dev box.

This spec adds that, and only that. It treats the VM the way the industry treats the JVM,
EVM, or amd64: as a **portable instruction-set architecture (ISA)** — a stable, auditable
contract that many substrates implement, each at the level it can afford. The reasoning
stack (v0.1–v0.5) is unchanged; this is a **vertical scale (tiny → full) beneath the
horizontal mixture of world models.**

Second, equal goal: make every *substrate-dependent* dependency (compute, vector memory,
language fluency) a **swappable backend behind a profile-aware interface**, so the ISA +
profiles are the invariant and implementations swap underneath per device.

### Current state of the VM (honest baseline)

- **Compiler (`cubelang`): 100% working** — source → bytecode is solid.
- **ISA (`cubemind/reasoning/vm.py`, `VSAVM`): Turing-complete, partial opcode coverage.**
  The control-flow + core ops work; some of the 47 opcodes' *operations* are not yet fully
  implemented. Built and tested as a component.
- **The VM is NOT linked into the runtime.** The live pipeline (`CubeMind.forward()`) runs
  *without* the VM (see §4). Wiring the VM in as the executive is explicit v0.6 work, not an
  assumption.

### Non-goals

- Re-designing axioms, world models, routing, discovery, reasoning decoder (v0.1–v0.5).
- Inventing a new VM. It exists; this spec formalizes + profiles + links it.
- Shipping silicon. Micro/Silicon/Neuro backends are a conformance roadmap; only `CL-Full`
  is reachable first.

## 1.5 Canonical reference & precise definitions

The authoritative definition of MoWM is the paper *"MoWM: Mixture of World Models via
Hypernetwork-Generated VSA Transitions"* (Grillcheese Research Laboratory;
`research_papers/md_src/MoWM - Mixture of World Models.md`). This spec uses its terms exactly:

- **A "world model" is a VSA transition function** `S_{t+1} = bind(φ(S_t), Δ_m(S_t,A_t))`,
  where `Δ_m` is generated by the m-th **HYLA hypernetwork** in block-code space. The
  **mixture** is M such models gated by **DSelect-k** (top-k, DisARM gradients):
  `mowm/world.py` (experts) + `mowm/router.py` / `cubemind/routing/moe_gate.py` (gate) +
  `cubemind/execution/world_manager.py` (specialist arena). **World models model *dynamics*,
  not knowledge.**
- **Perception frontends** (VS-Graph; `cubemind/perception/*` bio-vision/encoders) encode
  inputs → block-code; **memory stores** (hippocampal; `VectorStore`) retrieve. They feed the
  mixture; they are *not* themselves "world models." (Earlier drafts conflated these.)
- **Planning is algebraic:** `S_{t+H} = S_t ⊙ Π Δ_{m*}` — **O(k) bind ops, not k forward
  passes** — with cleanup every C=2 steps. **Value** is TD-free via **CVL** (occupancy
  measure + InfoNCE critic).

**Measured budgets (paper §4, 12 GB consumer GPU)** ground the per-profile `(k,l)` budgets:
block-code **bind 57 µs/op**, **similarity 4 µs/op**, FNet mixing 0.31 ms (L=256); typical
**M=4, k=2**; **`(k,l)` = 8×64 (d=512, dev) ↔ 80×128 (d=10240, production)**.

**Why this matters for the ISA:** world-model transitions *are* VSA bind operations, so they
map directly onto the ISA's VSA opcodes (`BIND_ROLE / UNBIND_ROLE / SEQ`) and the `(k,l)`
block-code dimension. A substrate that implements the VSA-binding opcode class
(**CL-Silicon and up**) can therefore run the mixture *and* O(k) algebraic rollout planning
**on-device** — the portable-ISA payoff is that MoWM's planning runs on a robot/FPGA, not
only the GPU. (Note: this means on-device *planning* needs ≥ CL-Silicon; CL-Micro runs only
the non-VSA numeric/control core.)

## 2. Core idea

1. **Formalize the existing 47-opcode VSAVM as a portable ISA** (fixed opcode set, defined
   state/execution model, stable bytecode encoding).
2. **Define four nested deployment profiles** — each an *opcode subset + (k,l) budget* — so a
   program emitted to the smallest profile runs everywhere.
3. **Put every substrate-dependent component behind a swappable, profile-aware interface.**
4. **Link the VM in as the executive** over the mixture (currently it is not).

```
        invariant:  ISA (bytecode) + Profiles
        swappable:  ComputeTier   {grilly GPU  | numpy CPU}
                    VectorStore   {Qdrant server | zvec embeddable}
                    FluencyLayer  {GGUF now      | cubby-lm later}
```

## 3. Architecture

### 3.1 The ISA — built, tested, partial, unlinked

| Role | Canonical home | State |
|---|---|---|
| **Reference interpreter** | `cubemind/reasoning/vm.py` (`VSAVM`, 47 opcodes) | Turing-complete, partial ops |
| **Bytecode encoding** | `opcode-vsa-rs/src/ir.rs` (synced enum) | canonical |
| **Compiler** | `cubelang/src/compiler.rs` | **100% working** |
| **Rust VSA primitives** | `opcode-vsa-rs/src/hypervec.rs` | working |

**Execution model.** Programs are lists of tuples `[(opcode, *args), …]`; `vm.run(program)`
executes with an instruction pointer + `LABEL`/`JMP`. State = `registers` (name → block-code)
+ `_values` (name → int) + a LIFO stack. Outputs: `QUERY`→int, `MATCH`→index,
`DECODE`→(label, confidence).

**The real 47-opcode set** (source of truth: `VSAVM`; *implemented-status to be audited in
Phase 0 — the Turing-complete arith+control+VSA core is confirmed; the advanced ops are
partial*):

| Class | Opcodes |
|---|---|
| **Arithmetic** (7) | `CREATE ASSIGN ADD SUB MUL DIV QUERY` |
| **VSA binding** (4) | `BIND_ROLE UNBIND_ROLE DIFF TRANSFER` |
| **Pattern** (5) | `DETECT_PATTERN PREDICT MATCH DISCOVER DISCOVER_SEQUENCE` |
| **Memory** (5) | `STORE RECALL CLEANUP REMEMBER FORGET` |
| **Data movement** (3) | `COPY PUSH POP` |
| **Control** (4) | `COND LOOP CALL JMP/LABEL` |
| **Sequence** (2) | `SEQ UNSEQ` |
| **Reasoning** (2) | `DEBATE ASK` |
| **Forge/adapt** (2) | `FORGE FORGE_ALL` |
| **Scoring** (2) | `SCORE DECODE` |
| **World mgmt** (1) | `SPECIALIZE` |
| **Exploration** (2) | `EXPLORE REWARD` |
| **Utility** (3) | `DESTROY COMPARE SKIP/PASS` |

**No transcendental opcodes.** There is no `sin/cos/sqrt/exp/log` in the ISA. Today those
physics-formula operators are evaluated numerically in **mowm `logic_engine.py`**, *outside*
the VM. This is a real profile-design constraint (see §3.2): a substrate that has the logic
engine (CL-Full) gets transcendentals for free; a VM-only substrate (CL-Micro/Silicon) does
**not**, and must either approximate (polynomial), gain new transcendental opcodes, or simply
not run those axioms.

### 3.2 Deployment profiles (nested), grounded in the real opcode classes

Profiles are **fixed** curated bundles, **nested**:

```
                 CL-Full
                /        \
        CL-Silicon      CL-Neuro
                \        /
                 CL-Micro
```

| Profile | Opcode classes (real) | `(k,l)` budget | Domains it can run | Target |
|---|---|---|---|---|
| **CL-Micro** | Arithmetic + Control + Data-movement + Utility (the Turing-complete core, all confirmed-working) | small, e.g. `k=8,l=64` (d=512), fixed-point | numeric/logical core *minus transcendentals* | robot MCU |
| **CL-Silicon** | Micro + VSA-binding + Sequence + Memory (cleanup) | medium, sparse | + symbolic binding / role-filler reasoning | FPGA / ASIC |
| **CL-Neuro** | Micro + Reasoning(`DEBATE/ASK`) + Exploration + SNN routing/hormones | event-driven | + debate / causal / exploratory reasoning | neuromorphic chip / reflex |
| **CL-Full** | all 47 + Pattern/Discovery + Forge + Scoring + `SPECIALIZE` + `logic_engine` (transcendentals) + multimodal + FluencyLayer | `k=80,l=128` (d=10240) | the whole pipeline | GPU / desktop |

**`(k,l)` is the per-profile resource knob** — block-code dimension is the dominant cost; the
codebase already runs `k=8,l=64` (fast CPU) and `k=80,l=128` (production), so profiles set it.

Conformance: a substrate implements one profile and **everything below it**. Bytecode is
identical across all; only the tier (interpret / AOT / native) differs. A **Profile
Validator** statically rejects a program that uses an opcode (or `(k,l)`) outside the target.

> Transcendental handling is the one cross-profile wrinkle (§3.1). Decision deferred to
> Phase 0: either (a) keep transcendental axioms `CL-Full`-only (logic_engine), or (b) add
> polynomial-approx opcodes to make them available lower. (a) is the YAGNI default.

### 3.3 Swappable backends (the load-bearing principle)

- **`ComputeTier`** — VSA / SNN / memory primitives. GPU: grilly (`backend/experimental/vsa.py`
  +14 shaders; `nn/snn_neurons.py` + `backend/snn.py` +11 shaders; `experimental/vsa/resonator.py`;
  `nn/capsule.py`). CPU: numpy via cubemind `ops/block_codes.py` (already a 3-level dispatch).
- **`VectorStore`** — Qdrant (server, the 6M corpus, `CL-Full`) ↔ **zvec** (Apache-2.0,
  in-process C++, HNSW/IVF/DiskANN, dense+sparse, hybrid retrieval, ARM64/RISC-V, Rust+Python
  bindings; `CL-Micro/Silicon/Neuro` on-device).
- **`FluencyLayer`** — VM result + context → natural language (**language only; never reasoning
  or program emission**). GGUF now → cubby-lm later (same interface).

| Component | Home | v0.6 role |
|---|---|---|

| SNN LIF/GIF/STDP | grilly `nn/snn_neurons.py` + `backend/snn.py` | ComputeTier / CL-Neuro |

Division: **grilly = GPU primitives · cubemind = VM + perception + memory + HYLA +

### 3.5 Coordination — current reality vs. target

**Current (built):**
- `CubeMind.forward()` is the live pipeline — **the VM is not in it** (§4).
- **WorldManager** evolves a specialist arena: per transition `r_obs = unbind(after, before)`;
  if `max_sim < τ` **spawn** else **consolidate** via Oja's rule + semantic decoupling.
- **Router** (`DSelectKGate` / `CubeMindRouter`) selects *which* specialists run.
- **Oracle** (`train_causal_oracle.py`) is a **learned future-proposer**: `oracle.top_k(state,
  action) → futures ranked by plausibility/Q`. This is the **"learned-proposes"** half.
- **VSA→symbol bridge exists** (`ops/vsa_bridge.py`: LSH→binarize→pack→`ContinuousItemMemory`;
  plus `CLEANUP`/cleanup-memory to re-symbolize noisy vectors).

**Target (v0.6 builds):** make the **VM the executive** over this mixture — route decisions
through it: WorldManager/Router/Oracle propose (learned), the **VM compiles the chosen
axiom/causal trace to bytecode, executes deterministically, and records it** (auditable). The
VM already has `SPECIALIZE` (→ WorldManager) and `SCORE/DECODE`; the gap is *threading the
runtime through the VM* rather than around it. **On routing:** the paper's mechanism is the **learned DSelect-k gate** (end-to-end via
DisARM) — fully learned, no VM. The "learned-proposes / VM-decides" (routing = C) overlay —
a deterministic, VM-*recorded* selection on top of the learned gate, for auditability — is a
**v0.6 proposal, not part of the paper's core**, and is the optional integration work in
Phase 2. Default keeps the paper's learned gate; the VM-recorded overlay is opt-in where an
auditable decision trail is required (e.g. a robot's safety-critical control).

**Reflex:** the live brain runs as a fast local reflex loop (`CL-Neuro`) and **escalates** to
the VM executive when the **afferent gate** trips (novelty / confidence shift / neurochemical
spike) — formalized over the existing GIF-fatigue + hormone mechanism (§5).

## 4. Data flow

**Current runtime (`CubeMind.forward()`, VM-less):**
```
Input → Perception (Harrier/Vision/Audio → block-codes) → fusion(bundle)
  → projection(_proj_in) → hippocampal context → memory retrieval (k-NN)
  → SNN-FFN → neurochemistry → neurogenesis → memory storage
  → projection(_proj_out) → output (block-code + confidence)
```

**Target (VM linked as executive):**
```
… perception/fusion/memory (as above)
  → route (WorldManager/Router/Oracle propose relevant specialists+futures, learned)
  → COMPILE chosen axiom/causal trace → bytecode (validated vs active profile)
  → VM.run (deterministic; SPECIALIZE→WorldManager, SCORE/DECODE, control flow)
  → result → FluencyLayer → natural language
```

## 5. Escalation protocol (name the existing mechanism)

GIF spike-frequency adaptation (fatigue/cycle-breaking) + hormones (urgency) already exist in
`neuromorphic_orchestrator.py`. v0.6 names escalation levels over them:

| Level | Behavior | Profile |
|---|---|---|
| 0 | local reflex, few steps, no proof | CL-Micro |
| 1 | cached axiom chains | CL-Silicon |
| 2 | full graph search + STDP routing + debate | CL-Neuro |
| 3 | discovery loop + multimodal | CL-Full |

Rising adrenaline/dopamine + GIF fatigue escalate; success de-escalates. No new control system.

## 6. Error handling

- **Profile mismatch:** Validator rejects out-of-profile opcode/`(k,l)` *before* run, with
  "needs profile ≥ X." No undefined execution.
- **Unimplemented opcode:** the implemented-status table (Phase 0) makes a partial op an
  explicit, surfaced error, never a silent wrong result.
- **No verified result:** FluencyLayer returns honest "couldn't compute," never a hallucination.
- **Grounding:** program literals must derive from prompt/world-state (anti-gaming).
- **Backend unavailable:** ComputeTier/VectorStore degrade by contract (GPU→CPU, server→embeddable)
  with a logged downgrade.

---

## 7. Testing & conformance

- **ISA conformance suite:** golden `(bytecode → result)` corpus; every profile backend
  reproduces it within its opcode subset → "robot and GPU run provably the same program."
- **Implemented-status audit (Phase 0):** test each of the 47 opcodes; mark working/stub/missing.
- **Cross-backend parity:** grilly GPU vs numpy CPU on VSA/SNN (reuse grilly's parity tests).
- **VectorStore parity:** Qdrant vs zvec top-k on a fixed index.
- **Profile Validator tests:** out-of-profile programs rejected; in-profile pass.
- v0.1–v0.5's ~2,900 tests cover the reasoning layer unchanged.

---

## 8. Relationship to existing specs

Orthogonal. v0.1–v0.5 = the **semantic** layer; v0.6 = the **execution substrate** beneath it
(portable ISA + profiles + swappable backends + VM-linking). Vertical scale (Micro ⊆ … ⊆ Full)
is independent of the horizontal mixture and the z-axis reasoning depth. Nothing is revised.

## 9. Phased rollout

- **Phase 0 — Formalize + audit (CPU-only, no GPU/silicon).** Classify the 47 opcodes by
  class + implemented-status; partition into profiles; decide transcendental handling; write
  the ISA contract; build the **Profile Validator** over the existing `VSAVM`. Deliverable:
  compile → validate-against-profile → run on `VSAVM` standalone.
- **Phase 1 — Complete opcode ops.** Finish the partial opcode operations needed by the
  targeted profiles (audit drives the list).
- **Phase 2 — Link the VM as executive.** Thread `CubeMind.forward()`'s decision step through
  the VM (compile chosen trace → bytecode → run); WorldManager/Router/Oracle become the
  learned-proposes feeding the VM-decides. Makes §3.5 real.
- **Phase 3 — Swappable backends.** `ComputeTier` (grilly↔numpy), `VectorStore` (Qdrant↔zvec)
  behind interfaces, profile-selected.
- **Phase 4 — FluencyLayer = GGUF** (language only, `CL-Full`).
- **Phase 5 — Edge backends.** `CL-Micro` interpreter (MCU), `CL-Silicon` (zvec memory, sparse
  VSA) on ARM64/RISC-V; `CL-Neuro` event path.
- **Phase 6 — cubby-lm swap-in** to the `FluencyLayer` once it is a solid *language* model
  (cubby's emission/SFT/RL path retired; its only job is the FluencyLayer interface).
